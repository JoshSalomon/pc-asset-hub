When comparing UI coverage between branches for a modified file, comparing uncovered line numbers directly (`branch_uncov_lines - main_uncov_lines`) produces false positives because code insertions shift all subsequent line numbers. A guard at L137 on main becomes L166 on branch — the set difference reports it as "new uncovered" when it's the same pre-existing uncov code.

**Correct method:** Only report a line as "new uncovered" if it appears in BOTH the git diff (new code) AND the coverage uncovered set. This is: `new_uncov = branch_uncov_lines & diff_new_lines` (intersection with diff), NOT `branch_uncov_lines - main_uncov_lines` (set difference with main).

**How to apply:** When running coverage comparisons for modified UI files, always cross-reference with `git diff ce581d4..HEAD -U0` to get the set of actually-new lines, then intersect with uncovered lines. The `scripts/uncovered-new-lines-ui.sh` script attempts this but has awk syntax errors on gawk. Use python instead.
