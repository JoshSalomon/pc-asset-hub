Critical lessons from TD Sprint (Session 030):

1. **Never claim test failures are "pre-existing" without running them on main first.** All 5 "pre-existing flaky" system test failures were regressions from this branch. CLAUDE.md says this explicitly.

2. **Always show covered/total, never percentages alone.** Percentages hide regressions. The coverage report must have statement counts for every package.

3. **Never delegate coverage measurement to subagents without verification.** Haiku agents produced fake numbers (wrong test counts, files not modified, fake 100%). Run the measurement commands yourself.

4. **Never change coverage measurement method mid-sprint.** Use `scripts/go-coverage-table.sh` on a fresh `coverage.out`. See `docs/coverage-measurement.md` for the reproducible method. If the baseline method seems wrong, verify it first — don't "fix" it.

5. **When removing test interactions, check coverage of affected components.** TD-79 auto-selected the version → removed version dropdown clicks from tests → lost coverage of MenuToggle/Select callbacks in CatalogVersionDetailPage. Always verify per-file coverage before and after removing test steps.

6. **UI coverage comparison must filter by git diff.** Comparing uncovered line numbers directly between branches produces false positives when code insertions shift line numbers. Use `scripts/uncovered-new-lines-ui.sh` (fixed awk in Session 030) which intersects git diff new lines with uncovered lines.

7. **Design UX changes before implementing.** TD-146 ⚠ icon was wrong on meta page tabs (permanent warning on all containment targets). Should only appear on operational tree groups with orphaned instances.
