### TDD rules (non-negotiable)

For every fix:
1. **RED**: Write a failing test that proves the bug exists. Run it. Watch it fail.
2. **GREEN**: Write the minimal fix. Run the test. Watch it pass.
3. **VERIFY**: Run ALL tests — `go test ./internal/... -count=1` and `cd ui && npx vitest run --config vitest.browser.config.ts`

For UI-only fixes where TDD is impractical (e.g., pre-selecting a dropdown), write the browser test FIRST, verify it fails, then fix the component.
